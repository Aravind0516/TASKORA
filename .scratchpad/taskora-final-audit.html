🟠 HIGH

HIGH-1 — Admin/Super Admin console has no Notifications bell and no Global Search

Where:
components/platform/platform-shell.tsx
Role affected:
ORG_ADMIN, SUPER_ADMIN
Evidence:
Grepped NotificationsMenu/GlobalSearch — both mounted only in components/layout/topbar.tsx (regular app shell), never imported by platform-shell.tsx.
Impact:
An admin working inside the console never sees "Daily Work Update Submitted," project-submission, or credit events land — they'd have to know to click their account menu → "User dashboard" to see anything.
Recommended fix:
Add <NotificationsMenu /> (and optionally <GlobalSearch />) to PlatformShell's header row, reusing the existing components as-is — no new backend work.

HIGH-2 — No organization-wide "Work Verification" view for admins

Where:
No file exists; closest analog is components/dashboard/manager-pending-reviews-card.tsx, scoped to projects the signed-in account personally manages.
Role affected:
ORG_ADMIN who is not personally a project manager on every project.
Impact:
An admin has no single place to see all pending Daily Work Update reviews across the organization — must open each project individually.
Recommended fix:
A new /admin/work-verification page reusing the existing dailyWorkUpdateService.subscribeToProjectDailyUpdates per-project pattern, fanned out across projectsInOrg() — a real, scoped, moderate-effort addition, not a security change.

🟡 MEDIUM

MEDIUM-1 — Project "Deliverables" tab is static mock data

Where:
lib/mock-data/deliverables.ts, imported by components/projects/project-detail-view.tsx.
Impact:
Every project shows the same canned deliverables list regardless of real project content — cosmetic-only tab.
Recommended fix:
Out of scope for a quick fix (needs a real schema decision) — but should be labeled clearly in the UI ("Preview data") or removed from the tab list before a real client demo, to avoid it reading as a real feature.

MEDIUM-2 — LinkedIn/Documentation/Meeting/Productivity credit categories have no dedicated candidate-facing submission flow

Where:
components/admin/award-credit-dialog.tsx — all 6 categories route through one manual admin action.
Impact:
Not a bug — a disclosed, deliberate scope decision from 3 phases ago (avoids inventing a fake meeting-attendance or LinkedIn-verification signal). Still worth flagging here since the audit explicitly asks whether automation is "real."
